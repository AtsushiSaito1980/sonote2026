# ep039 読み上げ用の台本（ブラウザの音声読み上げ向け）

## 『その手があったか』｜囲いが外れる前に、開く側に回る

### ホスト：戸倉ハジメ／約13分／ElevenLabs 用の `script_tts.txt` とは別物

### 書き方の方針（読み上げ対象外）

- **相手は無感情な機械の声。**演技で運べないものは、言葉で運ぶ
- フィラー（まあ・ええ・うん・そう。・で。）を置かない。抑揚が無いと、意味のない音になる
- 極端に短い単独文を連ねない。ブツ切れに聞こえる。1文はおおむね25〜50字
- 反語と「〜ですよね」を減らす。上がり調子が付かないので、ただの平叙文に聞こえる
- **接続詞を省かない**（ところが／そのため／一方で／つまり／ここまでが〇つめ）
- **今どこを話しているかを、こまめに言う。**耳だけの13分は、道しるべが無いと迷子になる
- 数字は必ず、直後に意味を添える。単体で置かない
- **分からなかったことは、分からなかったと言う。**尺があるぶん、都合の良い話だけにしない
- 間は改行。`[pause]` などのタグは使わない
- 英字はすべてカナに開く（イーユー）。読み上げが崩れるため
- **お題の答え4つは番組の見立てで、出典の記載ではない。**尺があるぶん、その断りを本文で厚くする
- 規制の是非・国どうしの比較・日本への導入予測には触れない

はい、始まりました。『その手があったか』。世の中の商売の、その手を持ち帰る時間です。戸倉ハジメです。

その前提が、ヨーロッパで切り替わります。

イーユー、日本語でいえばヨーロッパ連合に、データ法という決まりがあります。調べてみたところ、なかなか思い切った内容でした。

二〇二六年の九月十二日以降に、イーユーの市場へ出される「つながる製品」は、決まりが切り替わります。

つながる製品というのは、センサーを積んで、動いて、データを出すもの全般です。実務の解説で共通して挙がっている例を並べますと、産業機械、車両、家電、農業機械、それに通信につながる機器などです。ずいぶん広い範囲だと思われるかもしれません。実際、広いです。

これらの製品と、それに関連するサービスは、使う人がそのデータへ、はじめからアクセスできる設計にすることが求められます。

条件も、細かく決まっています。求められている状態を言葉にすると、こうなります。『使う人が、容易に、安全に、無償で、データにアクセスできること』。

ひとつずつ見ていきます。容易に、というのは、特別な手続きや交渉なしに、という意味です。安全に、というのは、途中で漏れない形で、ということです。無償で、というのは、データを見るために別料金を取らない、ということになります。

さらに、形式の条件もあります。構造化された、機械が読める形であることが求められます。人が画面で目で見る形ではなく、別のソフトが受け取って処理できる形、ということです。

ここは、少し補足を入れておきます。機械の稼働状況を、画面で見られるようにしただけでは、この条件は満たしません。画面は、人が見るためのものだからです。別の会社のソフトが受け取って、自動で処理できる形で出す必要があります。

つまり、見せることと、渡すことは、違います。この二つを分けて考えないと、対応したつもりで足りていない、ということが起こります。

そして、関連していて、技術的に可能な場合には、直接、リアルタイムでのアクセスも求められます。

ただし、ここには但し書きがあります。データを持っている側を介さない、直接のアクセス。この設計の義務は、絶対ではありません。技術的に可能な範囲に限られます。

ここは、大事なところです。必ず直接つながる仕組みを作れ、という話ではありません。できる範囲で、ということになります。

「関連していて」という条件についても、触れておきます。これは、直接かつリアルタイムのアクセスにかかる条件です。あらゆる場面で直接つなげ、という書き方にはなっていません。

決まりの文章は、こうした但し書きで細かく調整されています。見出しだけを読むと強く見えて、条文を読むと現実的、ということが起こりやすいところです。

ここまでが、ひとつめです。次に、実はその前段が去年から動いている、という話に移ります。

いま申し上げたのは、二〇二六年の九月十二日から、製品の設計そのものにかかる決まりです。

ところが、その一年前から、別の権利がすでに動いています。

二〇二五年の九月十二日から、イーユーの中でつながる製品を使っている人は、データを持っている側に対して、開示を求めることができるようになりました。使っている人というのは、企業も、消費者も含みます。

これだけなら、見せてください、という話にとどまります。

そうではありませんでした。もう一段、あります。

使っている人は、こう言うこともできます。このデータを、あの会社に渡してください、と。

渡す先を決めるのは、使っている人のほうです。そして、渡す先には、修理業者も、アフターサービスの事業者も、さらには競合他社も含まれるとのことでした。

つまり、去年の時点で、権利のほうが先に動き始めていた、ということになります。設計の義務は、あとから追いかけてくる形です。

権利が先で、ものづくりが後。この順番も、覚えておくと役に立つと思います。

なお、渡す側が丸腰になるわけでもありません。事業者の側は、渡したデータを相手がどう使うかについて、制限をかけることもできるとのことでした。何にでも自由に使ってよい、という話ではないようです。

どこまでの制限がかけられるのか。そこまで細かいところは、公表されている解説からは読み取れませんでした。実務では、契約の書き方に落ちていく部分だろうと思われます。渡さないことを前提にするのではなく、渡したあとの使われ方をどう書くか。そちらに手間をかけることになりそうです。

ここまでが、ふたつめでした。それでは、みっつめに移ります。きょうのお題です。囲いが外れたら、誰が、何を売れるのか。

先に、お断りしておきます。これから申し上げる四つは、出典に書かれていることではありません。制度の形から、こちらで考えた見立てです。

出典がはっきり書いているのは、渡す先に修理業者、アフターサービスの事業者、競合他社が含まれる、というところまでです。その先は、私の想像になります。そのつもりでお聞きください。

ひとつめの見立ては、独立系の修理と保守です。

これまで、機械の調子を先に読むには、作った会社の系列でないと難しい面がありました。稼働のデータが読めるのは、そちら側だけだったからです。それが開くと、系列の外にいる会社でも、壊れる前に手を打てるようになります。

たとえば、建設機械を何十台と持っている会社を思い浮かべてください。これまでは、それぞれのメーカーの保守に、個別に頼んでいました。稼働のデータが自分の手元に来るのであれば、まとめて一社に見てもらう、という選び方もできるようになります。

ふたつめの見立ては、中古の値付けです。

その機械が、どんな使われ方をしてきたか。丁寧に回してきたのか、限界まで使ってきたのか。これまでは、見た目と年式で推し量るしかありませんでした。履歴が第三者に開けば、査定のやり方そのものが変わります。

中古の業務用車両や、建設機械を思い浮かべると分かりやすいと思います。同じ年式でも、使われ方によって、中身はまったく違う状態になっています。それが数字で見えるなら、値付けの前提が変わります。

みっつめの見立ては、保険と、ファイナンスです。

実際の使い方に応じて、保険料やリース料を変えることが考えられます。走った距離ではなく、走り方で決まる、という言い方もできます。

事故を起こしていないことで割り引くのではなく、危ない使い方をしていないことで割り引く。そういう形も考えられます。判断の材料が、結果から、途中の記録に移ることになります。

よっつめの見立ては、複数のメーカーの機械を、横断して見る仕組みです。ここが、いちばん大きいかもしれません。

こうした仕組みは、これまでも試みられてきました。難しかったのは、メーカーごとにデータの出し方が違っていたからです。形式をそろえるところに、いちばん手間がかかっていました。その手間の一部を、決まりのほうが引き受ける形になります。

ひとつ、分からなかったことを申し上げます。この決まりが実際に動き始めたあと、こうした商売がどれくらい出てくるのか。まだ適用の前ですので、実例はありません。ここは、これから確かめていくところになります。

ここまでが、みっつめです。よっつめに移ります。これが、作った側にとって一方的な損とは限らない、という話です。

私は最初、この話を見たとき、メーカーが損をするだけの制度だと考えました。囲い込みを取り上げられるわけですから。

ところが、逆から見ると、違います。

囲いが外れるのは、自分の製品だけではありません。同じ決まりが、他社の製品にもかかります。

つまり、自社の機械のデータを渡す代わりに、よその機械のデータを扱う立場にも回れる、ということです。

守るか、攻めるか。同じ制度が、両方の入口になっています。

ここまでで、四つを見てきました。九月十二日から設計の義務が始まること。その前段の権利は、去年から動いていること。囲いが外れた先に、いくつかの商売が考えられること。そして、それは作った側にとっても入口になりうること。

ここから、商売の解剖に入ります。きょうの手は、囲いが外れる前に、開く側に回る。三つに分けてお話しします。

ひとつめ。囲い込みは、資産ではなく、前提です。

データを握っているから優位である、という商売は、決まりがひとつ変わるだけで、前提のほうが動きます。握っていることが強さの中身なら、その強さには期限があるかもしれません。

ここで確かめておきたいのは、自社の強さが、どちらの種類かということです。持っているから強いのか。使いこなせるから強いのか。前者は、制度で外れます。後者は、外れません。

同じことは、データ以外にも当てはまります。免許で守られている商売、資格で守られている商売、慣行で守られている商売。いずれも、守っているものが外から動かされる可能性があります。守られていること自体を強さと数えていないか。ここは、一度点検しておく価値があります。

ふたつめ。開くなら、自分から開いて、形式を決める側に回る、ということです。

これは、業界の標準を作る話にも近いところがあります。開くこと自体が決まっているのなら、どう開くかを決める側にいたほうが、有利です。
