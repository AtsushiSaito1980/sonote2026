# ネタの取り込み：$1

チャット（リポジトリの外）で集めたネタを、棚の形に整えて `ledger/backlog.yaml` へ入れる。
**採点はしない。**採点は `/patrol` が台帳とばらつきを見ながらやる。ここは整形だけ。

## 1. 対象を決める

`inbox/*.md` のうち、

- `ネタ集めの手引き.md` と `README.md` は**対象外**
- `ledger/backlog.yaml` に `source_md:` で参照済みのものも**対象外**（取り込み済み）

引数があればそのファイルだけ。無ければ未取り込みを全部。
**対象が0件なら、そう言って終わる。**空振りを隠さない。

## 2. 1件ずつ読む

front matter（`---` で囲まれた欄）と、8つの見出しの本文を読む。
欄が欠けていても止まらない。**欠けている欄は空のまま扱い、最後にまとめて報告する。**

## 3. backlog.yaml に1行足す

| 欄 | どこから |
|---|---|
| `id` | `bl0NN` の連番（既存の最大＋1） |
| `title` | front matter の `title`。無ければ本文の `#` 見出し |
| `gist` | **「これは何の話か」を1〜2文に詰める。**記号も内部用語も使わない普通の日本語。半年後にここだけ読んで思い出せること。**元の文が良ければそのまま使う** |
| `case_names` `industries` `region` `field` `subject` `tech` | front matter のまま。空なら本文から補える範囲で埋め、埋まらなければ空 |
| `trigger_on` | front matter の `trigger_on`。無ければ空 |
| `hand` `motive` `tailwind` | front matter のまま（`?` 付きの仮見立ても `想定` に直して残す） |
| `found_on` | front matter の `found_on` |
| `found_in` | `inbox` |
| `status` | **`inbox`。**ここでは他の値にしない |
| `reason` | **「巡回の外で拾った。未採点」**＋「裏取りの状況」から分かること |
| `revive_when` | 「まだ分かっていないこと」を、次に何が起きたら動くかの形に直す |
| `sources` | 「きっかけ」の媒体・URL。**不明なら「出どころ不明」と書く**。空にしない |
| `note` | 「数字」「どこで『へえ』と思ったか」「誰が、どこで儲けているのか」から、**使うときに効くもの**を拾う |
| `source_md` | `inbox/<ファイル名>`。**必須。**サイトから元の全文へ行くための紐づけ |

### 事実を足さない

**元の `.md` に書かれていないことを書かない。**数字も社名も日付も、知識で補完しない。
「推測」と書いてあるものは、`note` にも「（推測）」を付けたまま移す。

評価語（失敗・破綻・迷走・凋落・失速・二番煎じ）は、
**元の `.md` の中で出典に基づいて使われているとき以外、使わない。**

### 既に同じネタが棚にあるとき

`case_names` か `title` が既存の行と重なるなら、**新規追加しない。**
既存の行に `sources` を足し、`note` に inbox から分かった新しい手がかりを追記して、
`source_md` を紐づける。`status` は既存のまま触らない（採点済みの判断を上書きしない）。

## 4. トリガの窓を見る

`trigger_on` が制作日から31日を超えていたら、`reason` にそう書く。
**ただし取り込みは止めない。**鮮度切れは見送りの理由であって、捨てる理由ではない。

`trigger_on` が空なら `reason` に「トリガ未特定」と書く。

## 5. サイトに反映する

```bash
python3 scripts/build_site.py
```

「ネタ帳」ページに元の `.md` が全文で出て、ボツネタ棚の該当カードからそこへ飛べる。

## 6. 報告

- 取り込んだ件数と `bl0NN`
- **欄が欠けていたところ**（front matter の空欄・書かれていなかった見出し）
- トリガが窓外だったもの、トリガが無かったもの
- 既存の行に統合したもの

`.md` は**消さない。**細かいところは元のファイルにしか残っていない。
