# トリガ巡回

## 0.0. どの地域を巡回するか

引数（`$1`）に `国内` または `海外` があれば、その地域だけを探す。**指示が無ければ国内。**
頻度は決めない。ただし `spread.py` の海外側が長く空いていれば、候補に1件だけ混ぜて提案してよい。

**グローバルにするのは、ニュースの出所だけ。**台本も記事も日本語で、聞き手も変わらない。
海外を巡回するときは `config/sources.yml` の `hint_global` を見て、
CLAUDE.md §9 の5つの追加ルール（英語一次／原通貨／固有名詞を絞る／制度は地形／**日本への置き換え**）を守る。

## 0. 先にボツネタ棚を読む（省略不可）

`ledger/backlog.yaml` を開き、**復活できるものが無いか先に確認する。**
`revive_when`（復活の条件）が満たされていないかを、今回の巡回で拾った情報と突き合わせる。

- 条件を満たしていれば、**今日の候補としてそのまま提案する**（`bl0NN` のIDを添える）
- 満たしていなければ触らない。ただし新しい手がかりが出ていたら `sources` と `note` に追記する

新しく探す前にここを見る。**同じネタを二度探し直さないための棚**であって、書き捨ての置き場ではない。

### `status: inbox` の行は、扱いが違う

巡回の外（スマホのチャット）で拾って `/intake` が入れた行。**まだ一度も採点していない。**

- 復活候補ではなく、**今日の新規候補として採点の土俵に上げる**（他の候補と同じ表に並べる）
- 見立ての欄（`hand` `motive` `tailwind` `field` `subject` `tech`）は**チャット側の仮置き**なので、
  台帳とばらつきを見て**ここで確定させる**
- `source_md` があれば、その `.md` も読む。**数字の時点・裏取りの状況・まだ分かっていないことは、
  棚の1行ではなく元の `.md` に書いてある**
- 採点した結果その回で選ばなければ、`status` を通常の見送り理由（`overlap` `trigger_stale` など）に
  **書き換える。**`inbox` のまま残さない（未採点の意味が消えるため）

`inbox/` に `.md` があるのに棚へ入っていなければ、**巡回を始める前に `/intake` を実行する。**

## 0.5. いまのばらつきを見る（省略不可）

```bash
python3 scripts/spread.py          # 国内と海外を、別々に出す
python3 scripts/spread.py 海外     # 海外を巡回するときは、こちらだけ見る
python3 scripts/score.py           # これまでの3つの点数（面白さ・応用・ばらつき）
```

**ばらつきは地域ごとの別勘定。**今回巡回する地域の側だけを見る。
国内で3回前に使った手でも、海外では未使用なら ◎ になる（逆も同じ）。

**手（OP）・動機（MO）・風（TW）・型・畑・主役・技術度**の7軸について、
**いま何に寄っているか**と、**しばらく出ていない値（◎）**が出る。
探しに行く前にこれを見る。見ないと、探しやすい畑（生活消費）と探しやすい主役（会社）にばかり寄る。

**技術度の軸は、技術に寄せるためではなく「たまに技術の回を入れる」ため。**
高（研究・実証段階が主役）が5回以上あいたら、その回を1本探しに行く。

**◎の値を持つ候補を、最低1件は必ず出す。**見つからなければ「◎の◯◯で探したが窓内に無かった」と書く。

## 1. 6つの棚をスキャン

`config/sources.yml` の**6つの棚を全部**スキャンする（1棚でも飛ばすとテーマが偏る）。

1. 価格・営業・商品（オズボーン系の日次ニュース）
2. 制度（官報・審議会・パブコメ・条例審議）
3. 技術の節目（量産開始・実用化・受賞・特許切れ・価格逆転）
4. 提携（資本業務提携・協業・老舗×スタートアップ）
5. 決算（四半期ごとに在庫事例の再トリガ確認）
6. 人物・動機の節目（上場・資金調達・受賞・周年・事業承継・書籍出版）

**海外を巡回するときも棚は同じ。**見に行く先だけ変える（各棚の `hint_global`）。
検索は**英語で打つ。**日本語で探すと、翻訳記事しか出てこない棚がある。
候補の出典は英語の一次（企業のニュースルーム・目論見書・規制当局・官報）に到達してから出す。
**日本語のまとめ記事は一次として数えない。**

## 2. 出す前に必ず照合する

`ledger/episodes_log.csv` と `library/operations.md` を読み、

- 過去回と同じ題材は除外（T3定点観測を除く）
- 直近5回と同じ手・同じ主要業界は避ける
- **未使用の手**（operations.md の「使用済み」が空欄）を優先
- **今週まだ動機回（narrative）が無ければ、棚⑥から1本必ず入れる**
- 今週まだ技術・提携系が無ければ、棚③④から1本入れる

## 3. 出力（5〜7件）— 1件ずつ採点する

各候補について、まず素性：`トリガ（媒体・発表名・公開日）／手の候補（OP）／動機の有無（MO）／風（TW）／畑／主役／想定ホスト／なぜ今か／裏取りの難易度`

続けて**採点表**（`ledger/selection.yaml`）。表で出す：

| | Q1 | Q2 | C1 | C2 | C3 | C4 | C5 | 手OP | 動機MO | 風TW |
|---|---|---|---|---|---|---|---|---|---|---|
| 候補A | ○ | ✗ | ○ | ○ | ○ | ○ | △ | OP09 | なし | TW4 |

そのうえで**見立ての3つ**を出す（`scripts/score.py` と同じ数え方）。**足さない。**

| | 面白さ | 応用 | ばらつき |
|---|---|---|---|
| 候補A | 80 | 80 | 62 |

- **面白さ**（Q1 Q2 C1 C2 C5）… 聞きたくなるか
- **応用**（C3 C4 ＋ 手OP・動機MO・風TW が立っているか）… 持ち帰って使えるか。
  **タグが立たない候補はここで落ちる。**この企画の芯は、手と動機と風の組み合わせを
  新規事業に移せる形に抽象化することなので、そこを数字にしている
- **ばらつき**（7軸の冷え具合）… 前と違う回になるか

残り3つ（鮮度・裏取り・人物度）は**作ったあとに実測**するので、候補の段階では出さない。
ただし候補を選ぶときに、この3つが後で低く出そうかは見ておく。
**トリガが2週間以上前／出典が1系統／人が出てこない**候補は、そこが弱く出る。

**足切りは2段階。順に当てる。**

1. **核**：Q1・Q2 が**両方 ✗ なら、そこで落とす。**点数は見ない。儲けている主体も、動機を持つ人も出てこない回は、番組の問いに答えられない
2. **面白さ**：○ が3つ未満なら原則落とす。通すなら理由を書く

前提（トリガ1ヶ月以内／出典が一次か2系統／過去回と重複しない）を欠くものは、採点する前に外す。

最後に1行：「今週の充足状況（動機回◯本・技術系◯本・主役として未使用の手・◎の軸を拾えたか）」

### 型の変化球について（ep011の教訓）

編成ルール④「月2回以上は型の変化球を挟む」は**満たすべき条件であって、選ぶ理由ではない。**
T4数字回・T2失敗回・T5お題回でも、**核（Q1かQ2）は必ず立てる。**
T4は「数字のカラクリ」であって「統計の要約」ではない。統計そのものが主役の候補は、
その数字で儲けている主体か、その数字を作っている人が見えるまで、棚に置く。

## 4. 見たものを全部、棚に戻す（省略不可）

人間が1本選んだら、**残りを全部 `ledger/backlog.yaml` に追記する。**候補は消さない。

**5〜7件の一覧に載せる前に落としたものも書く。**手が立たなかった、日付が無かった、
というだけで捨てると、次の巡回で同じものを見つけて同じ判断をやり直すことになる。
そういうものは `status: idea`（種のまま）で置く。**探し直すコストのほうが高い。**

1件ごとに次を埋める。**`gist`・`status`・`revive_when` が本体**で、ここが空だと棚の意味が無くなる。

| 欄 | 中身 |
|---|---|
| `id` | `bl0NN` の連番 |
| `region` | `国内` / `海外`。**ばらつきが別勘定なので、棚も地域で引けるようにする**（空欄は国内） |
| `title` | 手が想像できる短い動詞句 |
| `gist` | **で、どんな話だったか**を普通の日本語で1〜2文。記号（OP／MO／TW）も内部用語も使わない。半年後に棚を眺めて、これだけ読めば中身を思い出せること。**省略しない** |
| `case_names` `industries` | 題材と業界（`;` 区切り） |
| `field` `subject` `tech` | **畑／主役／技術度。**`scripts/spread.py` と同じ値を入れる。「いま制度公共が7回あき」と分かったとき、棚から制度公共のネタだけを拾えるようにするための欄 |
| `trigger_on` | 見つけたトリガの日付。鮮度切れの度合いが後から分かる |
| `hand` `motive` `tailwind` | 現時点の見立て（OP／MO／TW） |
| `found_on` `found_in` | 発見日と、どの回の巡回で出たか |
| `status` | 下表から選ぶ |
| `reason` | **なぜ今回は選ばなかったか**を具体的に |
| `revive_when` | **何が起きたら復活するか**。ここが次回の自分への申し送り |
| `score` | 採点したときの点数（`面白さ60/応用40` の形）。一覧に載せた候補は必ず書く |
| `sources` | 見つけた手がかり（媒体・記事ID） |
| `note` | 使うときの注意、他候補との関係 |

| status | 意味 | 復活の見込み |
|---|---|---|
| `trigger_wait` | 手は立つ。窓内の発表がまだ無い | 高 |
| `trigger_stale` | トリガはあったが31日窓を外れた | 高（続報待ち） |
| `overlap` | 手・業界が直近5回と重なる | 中（数回あけて） |
| `unverifiable` | 一次資料に到達できない | 中 |
| `hand_weak` | 現象ではあるが商売の手に落ちない | 低 |
| `used` | 他の回に組み込んだ | 記録のみ |
| `dropped` | 復活の見込みなし | 記録のみ |
| `idea` | 手も日付もまだ無いが、面白いと思って拾った | 育てば |
| `inbox` | **巡回の外で拾い、まだ採点していない**（`/intake` が入れる。ここでは付けない） | 今日の新規候補 |

既に同じネタが棚にあれば、新規追加せず既存の行を更新する（`sources` を足し、`status` を見直す）。

`reason` には**採点の結果も書く**（「面白さ2/5・核なし」「畑が✗（直近5回に2回）」）。
点数が残っていれば、次の巡回で拾い直すかどうかを一目で決められる。

サイトのボツネタ棚は**新しい順が既定**で、古い順・復活の見込み順に並べ替えられる。

## 5. 選ばれた1本を採点表に残す（省略不可）

`ledger/selection.yaml` の `entries` に1行足す。

```yaml
  - {ep: ep012, Q1: ○, Q2: ✗, C1: ○, C2: ○, C3: ○, C4: ○, C5: △, note: "…"}
```

`note` には**なぜこの点になったか**を1〜2文。ここが後から基準を直すときの材料になる。
6つの点数は `scripts/score.py` が台帳・facts.yaml・記事から計算するので、書かない。

追記したら `python3 scripts/build_site.py` を実行して、サイトの「選び方」とボツネタ棚に反映する。
