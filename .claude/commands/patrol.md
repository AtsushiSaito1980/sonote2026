# トリガ巡回

## 0. 先にボツネタ棚を読む（省略不可）

`ledger/backlog.yaml` を開き、**復活できるものが無いか先に確認する。**
`revive_when`（復活の条件）が満たされていないかを、今回の巡回で拾った情報と突き合わせる。

- 条件を満たしていれば、**今日の候補としてそのまま提案する**（`bl0NN` のIDを添える）
- 満たしていなければ触らない。ただし新しい手がかりが出ていたら `sources` と `note` に追記する

新しく探す前にここを見る。**同じネタを二度探し直さないための棚**であって、書き捨ての置き場ではない。

## 1. 6つの棚をスキャン

`config/sources.yml` の**6つの棚を全部**スキャンする（1棚でも飛ばすとテーマが偏る）。

1. 価格・営業・商品（オズボーン系の日次ニュース）
2. 制度（官報・審議会・パブコメ・条例審議）
3. 技術の節目（量産開始・実用化・受賞・特許切れ・価格逆転）
4. 提携（資本業務提携・協業・老舗×スタートアップ）
5. 決算（四半期ごとに在庫事例の再トリガ確認）
6. 人物・動機の節目（上場・資金調達・受賞・周年・事業承継・書籍出版）

## 2. 出す前に必ず照合する

`ledger/episodes_log.csv` と `library/operations.md` を読み、

- 過去回と同じ題材は除外（T3定点観測を除く）
- 直近5回と同じ手・同じ主要業界は避ける
- **未使用の手**（operations.md の「使用済み」が空欄）を優先
- **今週まだ動機回（narrative）が無ければ、棚⑥から1本必ず入れる**
- 今週まだ技術・提携系が無ければ、棚③④から1本入れる

## 3. 出力（5〜7件）

各候補について：`トリガ（媒体・発表名・公開日）／手の候補（OP）／動機の有無（MO）／風（TW）／想定ホスト／なぜ今か／裏取りの難易度`
最後に「今週の充足状況（動機回◯本・技術系◯本・未使用の手）」を1行で添える。

## 4. 選ばれなかった候補を棚に戻す（省略不可）

人間が1本選んだら、**残りを全部 `ledger/backlog.yaml` に追記する。**候補は消さない。

1件ごとに次を埋める。**`status` と `revive_when` が本体**で、ここが空だと棚の意味が無くなる。

| 欄 | 中身 |
|---|---|
| `id` | `bl0NN` の連番 |
| `title` | 手が想像できる短い動詞句 |
| `case_names` `industries` | 題材と業界（`;` 区切り） |
| `hand` `motive` `tailwind` | 現時点の見立て（OP／MO／TW） |
| `found_on` `found_in` | 発見日と、どの回の巡回で出たか |
| `status` | 下表から選ぶ |
| `reason` | **なぜ今回は選ばなかったか**を具体的に |
| `revive_when` | **何が起きたら復活するか**。ここが次回の自分への申し送り |
| `sources` | 見つけた手がかり（媒体・記事ID） |
| `note` | 使うときの注意、他候補との関係 |

| status | 意味 | 復活の見込み |
|---|---|---|
| `trigger_wait` | 手は立つ。窓内の発表がまだ無い | 高 |
| `trigger_stale` | トリガはあったが31日窓を外れた | 高（続報待ち） |
| `overlap` | 手・業界が直近5回と重なる | 中（数回あけて） |
| `unverifiable` | 一次資料に到達できない | 中 |
| `hand_weak` | 現象ではあるが商売の手に落ちない | 低 |
| `used` | 他の回に組み込んだ | 記録のみ |
| `dropped` | 復活の見込みなし | 記録のみ |

既に同じネタが棚にあれば、新規追加せず既存の行を更新する（`sources` を足し、`status` を見直す）。

追記したら `python3 scripts/build_site.py` を実行して、サイトのボツネタ棚に反映する。
