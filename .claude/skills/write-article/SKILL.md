# note 記事＋概要欄

## note は独立媒体
**ラジオ・放送・番組・音声・リスナーへの言及と導線を一切置かない。** 素材（brief・facts）は共有するが、記事として一から構成する。文体は芸人口調を使わない書き言葉。

## 署名を置かない

note の投稿者は**人間本人の名前**で表示される。そこに書き手をもうひとり立てる必要はない。

- `文＝香月（編集部）` のような**署名行を書かない**（憲法§2-10。香月は制作上の人格で、外に出さない）
- 本文でも `編集部` を主語にしない。「編集部が整理した」ではなく、そのまま述べる
- 奥付も同じ：`本文の表現は、出典をもとに独自に構成したものです。企業名・商品名は各社の商標です。`

`scripts/check.py` が「香月」「編集部」の残存を FAIL で弾く。

## 文体：事実は言い切る、解釈は開く（personas/kazuki.md「借りて書く」）

記事は他人の取材・調査・開示の上に成り立つ。**断定してよいのは出典が言っていることまで。**そこから先の読みは、編集部の解釈として開く。謙虚さは断り書きや謝辞の一文で示すのではなく、**本文の言い回しそのものに出す**。

| ❌ 借り物の上で威張る | ⭕ 借りている自覚がある |
|---|---|
| 〜という装置なのである。 | 〜という装置なのだろう。 |
| 対象外の業界は存在しない。 | 対象外の業界は見当たらない。 |
| この赤字は必然的に生じる。 | この赤字は構造的に生じるものだろう。 |
| 三つの条件が要る。 | 成立には三つの条件が要りそうだ。 |
| 〜すればいい。／〜が早い。 | 〜のがよさそうだ。／〜から始めたい。 |

- **留保の言い回しは散らす**：〜のようだ／〜だそうだ（伝聞）／〜と読める／〜とみられる／〜のだろう／〜かもしれない。「〜と思う」の連発は読みにくい（`scripts/check.py` が回数を見る）
- 強い主張ほど本文で出どころを見せる（「報道によれば」「届出書の説明では」「会見では」）
- **日付・数値・固有の事実はぼかさない。**留保は1文に1つまで。全部を「かもしれない」にしない（わかりやすさを守る）
- 「編集部なりに整理した見方である」のような立場表明の決まり文句や、奥付の謝辞は置かない。**謙虚さは文面に出す**

## 見出しは、それだけ読んで中身が想像できること

章タイトルは比喩で凝らない。**その章に何が書いてあるかを、普通の言葉で言う。**

| ❌ 比喩で締めた見出し | ⭕ 中身が分かる見出し |
|---|---|
| 一、制度の時計 | 一、義務の中身と、施行までの日程 |
| 二、号砲の前に開いた店 | 二、施行前にもう開いている、四つの売り場 |
| 三、解剖 — 「引く」の構造 | 三、重さを取り除くと、勝負の軸が変わる |
| 四、この手の乗り方 | 四、自社の資産を、どの機能に当てはめるか |

- **`解剖 —` を見出しに付けない。**分析の章でも、何を分析したかを書く
- **`この手の〜` を見出しにしない。**「自社で試すなら、どこから」「自社の無料サービスに当てはめる」など、読者が何をする章かを書く

## 「手」に引っぱられた言い回しを避ける

番組名の「手」は本文の語彙ではない。本文で `この手` を主語にすると、毎回同じ癖の文章になる。**その回の中身を指す具体的な名詞に置き換える**（「無償公開は」「時間の置き場所を動かすことには」「この収益設計は」）。
`きょうの手` カードの見出しだけは残す。それ以外に「手」を持ち込まない。

## note は表に対応していない — 表は画像で貼る

note のエディタに表組みの機能はない。Markdown の表を貼ると崩れる。
**だから記事では表を書いてよい。**`build_site.py` が自動で処理する。

| どこ | 表の扱い |
|---|---|
| `article.md` | **そのまま Markdown の表で書く**（正本。アーカイブでは普通に表として出る） |
| note 貼り付け用の本文 | 表を外し、`［ここに画像を挿入：ep009-table-1.png（列名）］` に置き換わる |
| note 用の画像 | 表が1枚ずつ PNG になる（`figures` タブに並ぶ） |

- **表は3列までに収める。**画像にしたとき横に潰れる
- 表の直前の `##` 見出しが画像の見出しになるので、**見出しが表の中身を説明していること**
- 貼り付けたら、目印の行を消して画像を差し込む

## 冒頭は、具体で始める

note は冒頭の2〜3行がカードのプレビューに出る。ここが一般論だと手が止まらない。
**1行目に、固有名詞・数字・出来事のどれかを置く。**

| ❌ 一般論から入る | ⭕ 具体から入る |
|---|---|
| 無料で配るメディアの収益源は広告である | スーパーの精肉売場の頭上に、小さな画面が付いている。あれを全国で1万1,000台超まで増やした会社が上場した |
| 売り切りの商売は、商品を渡した日に代金が入る | 35万974点を貸し出し、33万6,950回まわった |
| 猛暑対策と聞くと、冷感グッズを思い浮かべる | 夜24時まで店を開けた日、18時以降の来店は約6,800人。通常期の約7倍だった |

- **自分の媒体の話から始めない。**「本誌はこれまで」「技術の回は」は、読者には関係がない
- 一般論を書くなら、**具体のあと**。掴んでから広げる

## note への貼り方（記事ページのボタン）

1. **タイトルをコピー** → note のタイトル欄へ
2. **本文を書式つきでコピー** → 本文欄へ。見出し・太字・引用・箇条書きがそのまま入る
3. `［ここに画像を挿入：…］` の行を、対応する画像に差し替える
4. **見出し画像**は `figures` タブの `cover`（1280×670）を設定する
5. 記事末尾の「あわせて読む」は自動で付く。公開したら **`ledger/note_links.yaml` に URL を書き足す**（次に書く記事から、リンクが実URLになる）
6. マガジンに追加する

書式つきが効かない環境では **Markdownでコピー** を使う（記号は残るので手で直す）。

## 制作の道具は、記事に出さない

note は外部公開。**どうやってネタを選び、どう作っているかは、こちらの持ち物**であって読者に見せるものではない。以下は記事にも概要欄にも書かない。

| 出さないもの | 代わりに |
|---|---|
| 手・動機・風の記号（`OP12` `MO1` `TW3`）とその一覧名 | 記号を使わず、その回の中身を普通の日本語で説明する |
| 「トリガ」「掛け味」「事実カード」「数字の系統」「並走句」「取材話法」 | 「きっかけになったニュース」など読者に通じる言葉 |
| 密度・型番号・巡回棚・ボツネタ・検査レポートへの言及 | 触れない |

**タグ欄は置かない。** 分類は `brief.yaml` と台帳に残っているので、記事に書く必要がない。
`scripts/check.py` が機械判定で弾く（記号や内部用語が残っていると FAIL）。

## タイトル（H1）は、そのまま note のタイトル欄に入る

note の投稿画面にタイトル欄は**1つだけ**。検索・おすすめ・SNS はここしか見ない。
**H1 には、連番も誌名も入れない。**「その手があったか #009」「週刊 その手があったか vol.001」は、読者の検索語ではない。シリーズであることはマガジンとハッシュタグが担う。

| ❌ H1 | ⭕ H1 |
|---|---|
| その手があったか #009 | 無料レシピ動画の会社が、スーパーの棚の上で黒字化するまで |
| 週刊 その手があったか vol.001 | カスハラ対策義務化の2ヶ月前に、もう開いていた四つの売り場 |
| その手があったか #003 | 夜24時まで店を開けたら、来店が7倍になった |

- **具体で始める。**固有名詞・数字・出来事のどれかを入れる
- **45字以内**（一覧で切れる）。`scripts/check.py` が長さと連番を見る
- H1 の直下に、その回の見立てを**太字1行**で置く（旧「特集｜」の前半にあたる部分）
- `特集｜` は紙の雑誌の記号なので使わない

## 固定フォーマット（本文 1,500〜2,000字・章は3つまで）

**短く書く。**通勤の片手間に最後まで読める長さに収める。章が増えるほど note 側で見出しを設定する手間も増えるので、**3章**に収める。

**「データ」欄は置かない。**数値の一覧を末尾に並べても、読者は読まない。**出典を挙げてあれば、正確な値は原典で確かめられる。**だから、
- **論を進める数字は本文に書く**（「経常損失13.7億円から、3Qで+3.2億円へ」）
- **論に効かない数字は書かない**（主幹事、公募株数、保有比率の端数）
- 数値の裏取りは `facts.yaml` が受け持つ。記事は読み物として成立させる

0. **AIの断り**（署名の直後）：`*本稿は生成AIを活用して制作しています。完全性・正確性を保証するものではありません。*`
   **末尾ではなく冒頭に置く。**読み始める前に知らせるのが筋
1. **きっかけになったニュース**（冒頭・引用ブロック）：媒体名または発表主体・発表名・公開日
2. 本文（3章。数値は本文の中で、必要な場所に置く）
3. **きょうの手**カード：教訓一行（**応用可能な原則の形。警句不可**）／使いどころ／最初の一歩（動詞終わり）
4. 出典（列挙）＋ 裏取りの注記（単独出典・要再確認などがあれば `※` で）
5. 奥付：`本文の表現は、出典をもとに独自に構成したものです。企業名・商品名は各社の商標です。`（AIの断りは冒頭にあるので繰り返さない）

### 削るときの順番

1. 同じことの言い換え（2回言っているものは1回にする）
2. 論に効かない数字（主幹事、公募株数、保有比率の端数など。**出典が受け持つ**）
3. 「なお」「ちなみに」で始まる補足段落
4. 章の統合（似た話をしている章は1つにまとめ、見出しを付け直す）

- 手法の正式名（デザイン思考・逆設定法・ERRC等）は **note でのみ**扱ってよい。ただし**自分の分類体系は別**で、これは出さない
- 読者募集・拡散施策は置かない

## shownotes.md（配信概要欄）
先頭に「▼ トリガになったニュース」、その後に note 導線、そのほかの出典、末尾に AI 制作表記。
**台本本編には注釈・免責・出典を入れない。それらは全部ここが背負う。**
