# inbox — 巡回の外で拾ったネタの受け口

`/patrol` は決まった6つの棚を回る。**そこに載らないところで見つけたネタ**を、
捨てずに持ち帰るための入口がここ。

```
スマホ                                    リポジトリ
────────────────────────────────────      ──────────────────────────────
ネタ集めの手引き.md を                     inbox/2026-08-23-xxx.md
チャットに添付                                    ↓
      ↓                                    /intake
Claude が聞く → 答える                            ↓
      ↓                                    ledger/backlog.yaml に
「書き出して」→ .md            ────→       status: inbox で1行
                                                  ↓
                                           build_site.py
                                                  ↓
                                           サイトの「ネタ帳」に出る
                                                  ↓
                                           次の /patrol が最初に読む
```

## ファイル

| | |
|---|---|
| `ネタ集めの手引き.md` | **スマホに保存して、チャットに添付するファイル。**チャット側の Claude はこれだけを読んで聞き役になる |
| `YYYY-MM-DD-*.md` | チャットから持ち帰ったネタ。**1ファイル＝1ネタ** |

## 置いたあと

```bash
/intake                       # inbox/ の未取り込みを backlog.yaml へ整形
python3 scripts/build_site.py # サイトに反映
```

`/intake` は取り込んだ `.md` を**消さない。**整形後の1行（`bl0NN`）は要約なので、
チャットで聞き出した細かいところ（数字の時点、裏取りの状況、まだ分かっていないこと）は
元の `.md` にしか残らない。**内に残すものは詳しいまま残す**という原則どおり、両方置いておく。

## なぜ backlog.yaml に入れるのか

棚を2つに分けると、`/patrol` が2箇所を見ることになり、いずれ片方を見なくなる。
**同じネタを二度探し直さない**という棚の目的からすると、入口が違うだけで行き先は同じでよい。

ただし `status: inbox` は他の見送り理由とは意味が違う。

- 他の `status` … **巡回で採点したうえで**見送った理由
- `inbox` … **まだ一度も採点していない。**台帳との重複もばらつきも見ていない

なので `/patrol` は step 0 で、`inbox` の行を**復活候補ではなく新規候補として**扱う。

## 手引きを更新したとき

`ネタ集めの手引き.md` を直したら、**スマホに置いてある古いコピーも差し替える。**
チャット側はリポジトリを見ていないので、添付されたファイルがすべて。
