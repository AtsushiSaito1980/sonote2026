## 1. 番組の核（不変）

### 1-1. テーマは縛らない。問いを縛る

引き算も、便乗も、制度変更も、技術開発物語も、輸入も逆輸入も扱う。一貫性は毎回同じ2つの問いで作る。

> **表の問い：「なんで、それで儲かるんですか？」**（構造）
> **裏の問い：「なんで、その人がやったんですか？」**（動機）

### 1-2. 番組の署名：看板と着地のずらし

AIの話が台所に着地する。空の話が防災と商売に着地する。柱は1つでも、オチで別の手に接続してよい。つかみの定型（3回に1回程度）：

> 「今日は◯◯の話をします。◯◯の話なんですけど、最後まで聞くと、なぜか△△の話になってる。そういうやつです。」

### 1-3. 固定の締め（一字一句変えない）

> 「きょうの手は、◯◯、でした。あなたの業界の当たり前、ひとつだけ動かすなら、どこですか。答えがひとつでも浮かんだら、それが、あなたの企画書の一行目です。それでは、また明日。◯◯でした。」

### 1-4. 聞き手に渡すもの

①雑談で使える面白ネタ ②自分の業界に置き換えられる構造 ③行動のきっかけ ④「自分でもできるかもしれない」という感覚。共感で終わらせず、主語を聞き手に戻して終わる。

### 1-5. 禁止事項（全コンテンツ共通・品質ゲートで照合）

| # | 禁止 |
|---|---|
| 1 | 「大企業だから仕方ない」等、諦めの正当化。会社・上司の悪口による共感取り |
| 2 | 説教（「挑戦しろ」の直接表現）。講義口調。リスナーを見下す表現 |
| 3 | 「情熱があれば」等の精神論での締め。無制約の天才譚だけの回 |
| 4 | カタカナ手法名（デザイン思考・破壊的イノベーション等）。**note限定で可** |
| 5 | 出典（事実カード）に対応しない数字・固有名詞 |
| 6 | 特定個人の失敗を嗤う話。個人の人格を扱うこと（会社と構造は扱う） |
| 7 | ダジャレ・キャラ芸。例え話は標準回2個まで、聞き手の生活・業務に接続するものに限る |
| 8 | 「いかがでしたか」等の定型句。台本内の注釈・免責・出典の読み上げ |
| 9 | **決め台詞・警句・ポエム調のまとめ**（対句・体言止めでキメる要約、「◯◯は、◇◇に隠れる」型の言い回し）。賢さの証明はこの番組の芸ではない |

## 2. 聞き手

企業の新規事業担当者・チームリーダー。企画、PoC、提案、稟議の日々。**フレームワークは知っている。足りないのは「自分ごと化できる具体例」と「月曜に試せる一手」**。通勤・家事の傍ら、画面なし、耳だけで完結する。

「困っている人」ではなく「まだ火が残っている人」として扱う。副次対象：家業の後継者、地方企業の企画部門、起業前の会社員。

### 3-5. ネタ選定基準（パイロット実証済み）

**大前提（鮮度）：各回には、制作日から1ヶ月以内に公開されたトリガ情報——本題に関連するニュース・プレスリリース・論文・統計・決算・法制化の動きなど——が存在すること。** 本題そのものの発生日は古くてよい。例：3月発売の製品でも、1ヶ月以内の試打記事・決算での言及・受賞・規制の動きがあればアンカーになる。Suicaの1995年の逸話も、直近の新改札ニュースをトリガに置けば使える。トリガが見つからない話題は、捨てずに寝かせて時機を待つ（ledgerに「トリガ待ち」フラグ）。**複数トピックを扱う回は、トピックごとにトリガ（1ヶ月以内）を紐づける。** 1ヶ月を超える情報を補助で使う場合は、台本・記事の中で時期を明示する（「去年の八月」「一昨年の調査」等）。聞き手は「この1ヶ月のニュース」のつもりで聞いている。

その上で、**5つのうち3つ以上**で採用。

1. 主役が意外（調味料会社が半導体／会社員の個人開発者／1946年の法律）
2. 立つ数字が1つある（13度／10万4359円／シェアほぼ100%）
3. 構造が転用可能（自分の業界に置き換えられる）
4. 教訓が一行になる
5. 耳だけで絵が浮かぶ（図解が要らない）

**NG**：相関図が必要な話／固有名詞が5つを超える話／出典が1つしか取れない・真偽が割れている話／個人の失敗を嗤う話。

## 4. パーソナリティと語り口

### 4-1. 体制

男女2名の芸人が**平日、日替わりで交互に1人語り**。TTSは1エピソード1声、声色の演じ分けはしない。鼎談（プロ×当事者×芸人）は「一人三役」で内包する（§4-5）。

**二人に共通する芸の土台＝「わからない側の代表」。** 有識者（取材先・資料・数字）に、リスナーが聞きたい素朴な質問を先に投げ、返ってきた答えを自分の言葉と自分の生活の実例で言い直し、「ってことですよね」と確かめながら進む。知らないことは知らないと言う（「これ、私も先週まで知らなかったんですけど」）。ただし卑下は口にしない——低い目線は態度で示す。うまい警句できれいに締めるのは、この番組では芸ではない。**わかっていく過程を聞かせること**が芸である。

### 4-2. 戸倉ハジメ（仮名）— 低温の解剖屋

44歳。元メガバンク法人営業7年。決算書が読める芸人。低め・遅め・間で聞かせる。つかみは**数字**から（「（数字）。これ、何の数字だと思います？」）。皮肉は構造に向け、人には向けない。香月の答えは、銀行員時代の言葉と自分の生活の実例に訳す。口癖（標準回1回まで）：「ここだけ持って帰ってください」。

### 4-3. 三崎アオイ（仮名）— 現場のテンポ屋

37歳。元精密機器メーカー生産技術6年。明るめ・やや速め。つかみは**場面**から（「まず、ある現場の話をさせてください」）。質問形でリスナーを巻き込む。香月の答えは、工程と現場の言葉に訳す。感嘆は1エピソード1回の大技。口癖（標準回1回まで）：「これ、現場やった人ならわかると思うんですけど」。

### 4-4. 香月（かづき）— 見えない放送作家

香月は制作上の人格であり、**放送には名前も声も登場させない**（初見の聞き手に説明できない固有名詞を増やさないため）。機能は4つ——①出典帰属の設計：台本上は**主語なしの取材話法**（「調べてみたら」「聞いてみたところ」「あとで確かめたら」＋伝聞の「〜だそうです」「〜とのことでした」）に変換し、出どころの気配だけを残す ②「取材の相手がいる」気配で1人語りの単調さを崩す ③品質基準の人格化（Claude Code上では構成・検査エージェント）④**有識者役**：制作過程でホストの素朴な質問を受ける。台本上は相手を名指しせず、質問『』→伝聞の答え→自分の言葉での言い直し、という形で現れる。

**作家としての方針：キメ台詞を書かない。** ホストに渡すのは、わからせるための質問・事実・言い直しの足場。要約は、ホストが自分の言葉で着地させる。台本を読み返して「うまいこと言ってる行」があったら、それは作家が前に出た事故として削る。

### 4-5. 一人三役（1エピソードに各1回以上）

| 役割 | 技法 |
|---|---|
| 当事者・有識者 | 『』で質問と答えのやり取りを再現する。相手は名指しせず、「聞いてみたら」「調べたら」＋伝聞の「〜だそうです」で運ぶ（発表主体・役職名は言ってよい。逐語引用ではない。§7-3）。声色は変えない。前後に間 |
| 翻訳者（本人） | 「ここから、商売の解剖です」と宣言し、答えを自分の言葉と生活の実例に訳して、他所へ持ち出せる形（条件＋動作）に直す |
| 芸人（本人） | 聞き手が引っかかる場所で、先に自分が引っかかる（素朴な疑問・驚き・確認）。うまいことは言わない |

### 4-6. 共通の語り口（文体ルール）

- 頭のいいお笑い芸人が、わかりやすく伝えるトーン。構成は骨太に
- 一文は短く。体言止め、倒置OK。読点で息継ぎを作る
- 専門用語は必ず日常の比喩に翻訳する（成層圏＝ビルの空きフロア、ABF＝層の間の膜、副産物＝会社の裏口に積んであるあれ）
- リスナーと並走する。「〜と思うじゃないですか」「ありますよね」。見下さない、講義しない
- 数字は耳用に丸める（前年同期比154%→およそ1.5倍）。**正確値はnoteと納品メモに残す**
- 教訓は一行にするが、**気の利いた警句ではなく、他所へ持ち出せる原則の形**で言う（「売上が減った時間を見つけたら、客がどの時間に移ったかを先に調べる」）。対句・体言止め・ポエム調のキメは禁止
- 締めの手前に、動詞で終わる行動指示を1つ（「業界の当たり前を、紙に10個書き出してください」）
- 過去回コールバックは月1回程度。前任ホストの回への言及も可（連続性の装置）
- 実在企業は事実ベースで、敬意を持って扱う
- **リズム則：情報を3つ連射したら、素朴なひと言（疑問・驚き・自分の実例・確認）で息継ぎを入れる。「言い当て」でキメない**
- **翻訳則：制度用語・調査用語・専門用語は、初出時に一度だけ日常の言葉に置き換える**（措置義務→宿題、PIT作業→整備の受付、など）

**文体対比表（レビュー時の判定基準）**

| ❌ キメ（作家の声・禁止） | ⭕ 聞き上手（芸人の声・採用） |
|---|---|
| 「体より先に、予定のほうが暑さから逃げてる」 | 「体がまいる前に、みんな予定の側を先に変えてるんだ。私も昼の散歩、朝にしました」 |
| 「営業時間って、実は在庫なんですよ」 | 「聞いてみたら、営業時間も棚と同じで動かせるんだそうで。ああ、売り場の模様替えと同じ扱いってことか」 |
| 「客は消えない、時間に隠れる」 | 「客が減ったんじゃなくて、別の時間に移ってる。だから、減ったと思ったら、先に移った先を探す」 |

### 4-7. 情報密度パラメータ（brief指定・調整可能）

語りの肉付け（並走句・自問自答・反復・余談）と情報量の配合は、briefの `density` で切り替える。**既定は balanced＝dense水準の情報量を、芸人の語りで運ぶ**。

| density | 狙い | facts消化数 | 数字上限 | 固有名詞上限 | 例え話 | 並走句・自問自答 |
|---|---|---|---|---|---|---|
| dense | 情報主体。速報・数字回向け | 8点以上 | 6 | 7 | 1 | 合計2回まで。同義の言い直し禁止 |
| **balanced（既定）** | 情報はdense寄り、語りは芸人寄り | 7点以上 | 5 | 6 | 2 | 合計3〜4回 |
| narrative | 人物・動機中心の回（動機回・週1本。型3を使用） | 4点前後 | 3 | 4 | 2 | 制限なし。ただしキメ禁止・説教禁止は同様に適用 |

共通ルール：口癖1回・『』再現1〜2回・教訓一行と宿題は必須。noteは常に正確値を持つ。**香月への質問・答えの確認（「ってことですよね」）と、他業界への応用例は、並走句・例え話に数えない**（聞き上手の芸の本体のため）。

## 5. ラジオ台本仕様

### 5-1. 尺

- **標準：5分＝本編1,700〜2,000字・平日1日1回配信（月〜金）**。現在はパイロット運用
- **拡大版：18分＝5,400字前後**。指定時のみ（総集編・特集）。構成はv2のP0〜P6を使用
- brief の `duration_min` で指定。以下は標準5分の仕様

### 5-2. 構成（どちらかの型）

**型1｜一本深掘り型（基本)**

| パート | 字数目安 | 内容 |
|---|---|---|
| OP定型 | 60 | 「はい、始まりました。『その手があったか』。世の中の商売の、その手を持ち帰る時間です。◯◯です。」 |
| つかみ | 200 | ホスト別の型（数字／場面）。冒頭30秒に謎か意外性。トリガの時点と発表主体を、ここか本命の導入で口頭明示（「先月◯◯が発表した」等。媒体名は任意） |
| 背景〜展開 | 900 | どんでん返しをひとつ。『』再現をここで |
| 解剖 | 400 | 宣言→構造→**きょうの手の名指し**→核心の一行 |
| 持ち帰り | 200 | 翻訳ひと言＋宿題（動詞終わり） |
| ED定型 | 140 | §1-3の固定文（教訓一行を◯◯に代入） |

**型2｜小ネタ＋本命型**：小ネタ2つ（各150〜250字、テンポ重視）→「さあ、本命です」→本命（800〜1,200字）→共通構造の抽出→ED定型。

**型3｜人物深掘り型（動機回・density: narrative）**

| パート | 字数目安 | 内容 |
|---|---|---|
| OP定型 | 60 | 共通 |
| つかみ | 200 | ホスト別の型。トリガの時点明示 |
| 商売の輪郭 | 250 | 何をして、どう儲けているか（短く） |
| 引っかかった瞬間 | 420 | 動機の「場面」。『』趣旨再現。**この型の核** |
| 反対・制約 | 230 | 逆風・慣行・葛藤の記録（無い事例は動機回にしない） |
| 現在と節目 | 220 | 直近トリガ（提携・受賞・上場等） |
| 解剖 | 300 | 動機の型（MOタグ）を、他所へ持ち出せる条件＋動作に一般化。説教にしない |
| 宿題＋ED定型 | 240 | 共通 |

### 5-3. 上限（標準回）

数字・固有名詞・例え話・並走句の上限は §4-7 の density 指定に従う（既定 balanced：数字5・固有名詞6・例え話2）。口癖1回・『』再現1〜2回は密度によらず共通。拡大版は各1.5〜2倍まで。

### 5-4. 音声化ルール（ElevenLabs v3・パイロット実測）

**script_tts.txt は、ElevenLabsのテキスト欄にそのまま貼って生成できる完成稿とする。** タイトル・見出し・話者ラベル・注釈・メタ情報を含めない（本文とオーディオタグのみ）。英字・略語はカタカナに展開し、数字は漢数字で書く。

- モデル：Eleven v3。ボイス：戸倉回＝男性、三崎回＝女性（日本語サンプル収録の声）。Stability 0.5〜0.7
- オーディオタグは**段落頭に1つまで**。5分尺で4〜6個を目安に、感情が切り替わる段落の頭へ置き、同じ調子が続く段落では省略する。使用セット：[bright] [curious] [serious] [excited] [thoughtful] [warm]（三崎回・静かな回は[calm]追加可）
- **三点リーダー「…」は使用禁止**（そのまま読まれる事故）。間は読点・改行・段落で作る
- **半角スペースでの分かち書き禁止**（ブツ切りの原因）
- 漢字は**テスト駆動で開く**：先回りで全部開かない → 生成して誤読した語だけ直す → 部分開き（空飛ぶ→そら飛ぶ）か、言い換えて難読語ごと消す → カタカナよりひらがな
- 駄洒落になっている漢字は開かない（例：家系図）
- 初出の難読語は、かなを添えて紹介する（**「獺祭、だっさい」方式**）
- 誤読が確定した語は `library/dictionary.yaml` に開き方を登録し、tts-format が以後自動適用（テスト駆動の資産化）
- 公開前に**人間が1回通しで聴く**（必須・省略不可）

### 5-5. 音楽

OP/EDにテーマ曲、頭と尻だけ音量を上げる。本編BGMは敷かないか、敷くなら歌なしインストで語りより12〜15dB下げる。組み立てはElevenLabs Studioのタイムラインで、頭尻にフェード。

## 6. note仕様（週刊誌型）

### 6-1. 形式

パイロット `weekly-tane vol.1` の週刊誌フォーマットを正式採用。記事はラジオ各回に連動して**平日毎日1本**発行（通し番号#NNN）。週次まとめ号「週刊 その手があったか」は土曜に任意発行。語り手は**香月名義**（編集部の解説文体。芸人口調は使わない）。

**noteは単独で成立する独立媒体とする。** 本文・見出し・データ欄・奥付・募集文のどこにも、ラジオ・放送・番組・音声への言及や導線を置かない。素材（brief・facts）は共有するが、記事は台本の再構成ではなく、記事として一から構成する。

### 6-2. 各特集の必須要素

1. **今回のトリガ**：冒頭に、起点となった情報源を明記（媒体名または発表主体・発表名・公開日）
2. 本文（図解・年表・データ欄を活用した、単独で読める記事）
3. **「きょうの手」カード**（タネ袋の後継）：教訓一行（**応用可能な原則の形。警句・ポエム調は不可**）／効く日（まき時）／最初の一歩（発芽条件・動詞終わり）
4. タグの明記：手（OP）・動機（MO）・風（TW）
5. 主要数値は**正確値**で記載する（数字の丸めはしない）
6. 手法の正式名（デザイン思考・逆設定法等）は**noteでのみ**扱う
7. 出典（特集末尾に列挙）

### 6-3. 号末の固定要素

- **出典一覧**（本号で参照した主な資料）
- 奥付定型文：「記事中の数値・事実は文末の出典に基づき、表現は編集部が独自に構成したものです。企業名・商品名は各社の商標です。本誌の制作には生成AIを活用しています。」
- 読者募集・拡散施策は行わない（読者数・PVは目的ではない）。「業界の当たり前」の在庫は自前と身の回りから集め、ledgerに蓄積する

## 7. 著作権・法務ガードレール

### 7-0. 方針：台本はクリーンに保つ

**台本・放送音声に、注釈・免責・出典の読み上げ・AI表記を入れない。** 適法性は次の3つが背負う。

1. **構造**：事実カード化と自動検査（§7-2）。人の注意力ではなく、パイプラインの形で守る
2. **メタデータ**：配信概要欄（出典一覧・AI音声制作の一行表記）と納品メモ
3. **話法**：本編内で出どころに触れたい時は、主語なしの取材話法だけを使う（「調べてみたら」「聞いてみたところ」＋「〜だそうです」。発表主体・役職名は言ってよいが、個人名・媒体名・制作スタッフ名は出さない）

### 7-1. 前提の要点（設計の根拠）

- 無償配信・AI表記は**免罪符にならない**。非営利無償の例外（38条）は公衆送信に適用されない
- **事実そのものは自由、記者の表現・構成は保護される**。最大の地雷は「1本の記事の要約」＝翻案の経路
- よって本番組は「ニュース要約」ではなく**「自分の視点の解説番組」**に寄せる。事実は素材、主役は解剖と教訓。これが法的にもコンテンツとしても最強のガードレール
- 名誉毀損は非営利でも成立する。AIの誤りを断定調で読み上げない
- 新聞社対AI検索の訴訟が係争中（2025年提訴・2026年審理中）。判決で本節を見直す

### 7-2. 三層ファイアウォール

```
第1層 入力 → 第2層 変換（ここで原文を捨てる）→ 第3層 検査
```

**第1層｜入力**
- **アンカー（トリガ情報）は制作日から1ヶ月以内の公開物。** 本題に関連するニュース・リリース・論文・法制化の動きであれば足り、本題自体の日付は問わない。1ヶ月超の情報は背景・補助として使用
- 収集元は `config/sources.yml` 登録済みのみ（robots.txt・利用規約を確認して登録。AI利用拒否サイトは登録しない）
- **sources.yml は6つの巡回棚で構成し、毎朝のスキャンで全棚を必ず舐める**（探索の偏り防止）：①価格・営業・商品（オズボーン系の日次ニュース）②制度（官報・審議会・パブコメ・条例審議）③技術の節目（量産開始・実用化・受賞・特許切れ・価格逆転）④提携（資本業務提携・協業・老舗×スタートアップのリリース）⑤決算（四半期ごとに在庫事例の再トリガを確認）⑥**人物・動機の節目**（上場・資金調達・受賞・周年・事業承継・書籍出版。創業物語は、この節目の瞬間に再点火する）
- 一次情報を優先（プレスリリース・官公庁統計・決算資料・本人インタビュー）。Wikipediaは補助のみで、キー事実の単独ソースにしない
- **キーとなる数字は2ソース以上、または一次資料**で確認（confirmed_by >= 2）

**第2層｜変換：事実カード化**
- extract-facts が sources/ を読み、`facts.yaml` に変換して**以降の工程には原文を渡さない**
- スキーマ強制：who / what / value / when / source_url / confirmed_by。各フィールドは**短い名詞句・数値のみ（15字以内）**。形容詞・評価語・比喩の記入禁止（記者の表現が混入する余地を消す）
- 当事者の発言は quote card（趣旨・話者・出典）として別管理

**第3層｜検査（checker）**
- 原文との**形態素5連続以上の一致 → NG**（『』再現部にも同基準を適用）
- **事実カード外の固有名詞・数値の混入 → NG**（ハルシネーション検知）
- 事実カードとの出典対応が取れない記述 → NG
- **リスク語（ng.yml）× 実名の共起 → 自動でなく人間確認に昇格**
- 自分の言葉（解剖・ツッコミ・翻訳・教訓）の比率 **40%未満 → NG**（引用従属性と番組価値の両方を担保）
- 落ちたら自動リライト→再検査。**3回失敗で人間にエスカレーション**

### 7-3. 発言再現ルール

『』は**趣旨の再現**であり、逐語引用ではない。言い回しを変え、形態素5連続一致基準を満たすこと。realモードで、出典にない発言を創作しない。

### 7-4. モード

- **real（標準）**：三層通過が条件。パイロットで実証済みの運用
- **fictional（退避先）**：複数実例の合成、センシティブな題材の再構成に使用。概要欄に「実在の事例をもとに再構成したフィクションです」を明記

### 7-5. 規約面（設計時に一度）

- TTS側：使用ボイス・キャラクターの利用規約を確認（政治・宗教・なりすまし条項）。制限のあるボイスは、該当トピックで自動回避するようボイス分岐
- 配信先（YouTube / Spotify / stand.fm 等）：AI生成コンテンツの開示要件・再利用コンテンツポリシーを確認し、要求される開示は**概要欄側で**満たす

### 7-6. 監査証跡

episodes/ 配下（sources → facts → drafts → review）が生成過程の証跡としてそのまま残る。GitHub運用なら履歴が自動で付く。万一の照会時に、過程を提示できる。

### 7-7. 免責

本節は設計上の整理であり、法的助言ではない。運用開始前と、係争の判決時に、専門家への確認を推奨する。
